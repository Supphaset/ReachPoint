# 0016 — Automatic desk review followed by human approval

Date: 2026-10-15. Status: **Accepted by the user** in this chat: AI gets a text address and coordinates from Google Maps, proposes boat/truck and emergency level, and writes optional volunteer preparation notes; “these will automatically reviewed by the ai and human will approve this”.

The desk shows these results together, followed by **Approve review** and **Edit details**. AI review starts automatically for new/unreviewed caller records when the existing AI runtime is enabled. All AI results await human approval, including routine requests. Approval records its actor and time separately from AI/Human review provenance. The original rule required address, coordinates, transport and emergency level; this completeness gate is superseded by [0018](0018-minimal-desk-approval.md), accepted 16 Oct 2026. Only original phone, help type and submitted location are now required; derived fields and notes may remain unresolved. Humans may save incomplete corrections for follow-up. Corrections or changed caller input clear the current approval, preserving history. Approval is operational review, distinct from creating a validated case, assigning a team, clearing a route, clinical assessment, or confirming delivery.

Location resolution is a tool step in the automatic review pipeline, not invented model output. Supported Google Maps links supply destination coordinates and location text; viewport/camera coordinates are not pickup pins. Short links follow bounded redirects restricted to Maps hosts. Optional Google Maps Geocoding supplies a formatted address from a place/address/pin when configured and explicitly enabled. Unknown, ambiguous or failed lookups remain for correction. The original caller fields are retained, with location proposals/history in the separate review record. Dedicated addresses, coordinates and phone numbers are not sent to the classification model.

Full address lookup needs a server-side `GOOGLE_MAPS_API_KEY` and `REACHPOINT_MAPS_GEOCODING=on`; it defaults off. No Maps billing or new paid service is enabled by this implementation. Tests use synthetic locations and mocked provider responses. The existing local Gemini budget is recorded separately in [0015](0015-local-gemini-demo-budget.md).

Local configuration update, 16 Oct 2026: the user supplied Gemini, Pinpoint and Google Maps keys in a local `.env` and requested retrying the workflow. Load that file explicitly through Uvicorn's `--env-file` option and enable the existing, already-enabled Geocoding API lookup. No credentials are stored in the repository. Reverse lookup accepts Google's ordered address hierarchy, uses the first result when complete and retains the exact submitted pin; multiple forward/place matches still remain unresolved. Address suggestions continue to require human approval. See [Google's reverse-geocoding response guidance](https://developers.google.com/maps/documentation/geocoding/guides-v3/requests-reverse-geocoding), accessed 16 Oct 2026.

Optional preparation notes reach an accepted active team job after human approval. Pending notes remain visible at the desk. Closing/handing back the job still removes them from that team's view.

Sources accessed 2026-10-15: [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), [Geocoding](https://developers.google.com/maps/documentation/geocoding/requests-geocoding), [Reverse geocoding](https://developers.google.com/maps/documentation/geocoding/requests-reverse-geocoding). Shared-link encodings can vary; unsupported links remain unresolved rather than guessed.
